# MT7981 RAM study: Tailscale 1.103.0 development snapshot

This study measured an ARM64 build on a Globitel BT-RB300 router. It is
independent of the MIPS TR1200 package-size experiment in
[TR1200-v1.98.3.md](TR1200-v1.98.3.md). The source changes and runtime results
have not been ported to the TR1200.

## Test setup

- Router: Globitel BT-RB300, MediaTek MT7981, two CPUs, 256 MiB physical RAM
- OS: OpenWrt, Linux 6.18.44, ARM64, kernel TUN, no swap
- Daemon: Tailscale `1.103.0-dev20260924`, source commit `b1664580dc50`
- Go: 1.27.1, `CGO_ENABLED=0`
- Tailnet: Headscale control plane, five peers; direct and forced-DERP paths
  tested separately
- RSS came from `/proc/PID/status`; PSS was unavailable on this kernel.

The chosen `openwrt-small-nodebug` build kept the netstack and real DNS
transport. The test included UDP and TCP DNS, direct peer traffic, TSMP, DERP,
TCP in both directions, UDP bursts, and a two-hour soak. The soak used seven
bidirectional TCP bursts and ended with a quiet interval. It does not cover
unbounded peer churn or every possible ACL and routing configuration.

## RSS results

All sizes below are MiB (1 MiB = 1,048,576 bytes). Connected-idle values are
medians after warm-up; soak values are the median of the final ten minutes.

| Build | Connected idle RSS | Two-hour final-window median | Soak peak RSS |
| --- | ---: | ---: | ---: |
| Upstream, default runtime | 40.15 | 41.75 | 49.59 |
| Upstream, `GOGC=10` | 35.28 | 39.28 | 42.15 |
| `openwrt-small-nodebug`, `GOGC=10`, `GOMEMLIMIT=24MiB` | 24.95 | 25.22 | 27.81 |

The selected build used 7.53 MiB `RssAnon` and 17.70 MiB `RssFile` in the last
ten minutes of the soak. Its live Go heap was 2.97 MiB and it had 66 goroutines;
the two upstream variants had 81. RSS at the end was 25.06 MiB. No OOM or
unexpected restart was observed during this fixed test.

The idle result was about 38% below upstream/default and 29% below
upstream/`GOGC=10`. In the soak's final window, it was about 40% and 36% lower,
respectively. This is a measured workload result, not a hard memory ceiling.

## What the selected profile changed

The build combined runtime settings with code and feature changes:

- `GOGC=10` and the soft Go runtime memory target `GOMEMLIMIT=24MiB`.
- Smaller initial WireGuard-go Linux TUN GRO capacities that grow on demand;
  batch limits were retained.
- Clearing references to packet buffers after synchronous writes, so GC can
  reclaim completed traffic slabs.
- Disabling log uploads and optional features such as Tailscale SSH, Serve,
  Taildrop, cloud integrations, and debug/pprof in the nodebug profile.
- Keeping the netstack and DNS transport. An earlier lower-RSS profile without
  netstack was rejected because it broke ordinary UDP/TCP DNS transport.

`GOMEMLIMIT` is a soft limit for Go-managed memory, not a process RSS cap. A
12 MiB setting in the runtime grid caused roughly 40% of one CPU core to be
spent in GC during the tested transfer and was rejected. The 24 MiB value was
chosen on MT7981; it is not a recommendation for the slower MT7628.

The short TCP phase measured 323.2/381.3 Mbit/s RX/TX for the selected build
and 326.7/385.0 Mbit/s for upstream/default. Daemon CPU was 144.5% versus
144.6% of one core during that particular bidirectional test. These readings
showed no material penalty in that test, but do not predict CPU cost on a
single-core MT7628 router.

## MinScale status

The measured memory profile depended on a Tailscale development checkout and
two local WireGuard-go patches. The MIPS v1.98.3 script in this repository
does not contain those patches and does not set `GOGC` or `GOMEMLIMIT`. Porting
the profile to a current stable release and measuring CPU, RSS, DNS, and
throughput on MIPS is still required before those settings or patches can be
recommended for the TR1200.
